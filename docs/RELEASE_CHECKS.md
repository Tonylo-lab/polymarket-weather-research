# Release checks / 发布检查

Prepared 2026-11-13 from directly read local source, in a separate directory. The original project was treated as read-only. No Bot/service/task was started or stopped, no wallet or account credentials were accessed, and no real order or financial database operation was performed.

The release has a fresh Git history and an explicit tracked-file allowlist. It includes computational source, English/Chinese documentation, synthetic generation, numerical/offline safety tests, MIT and third-party notices, and numeric historical aggregates. It excludes original Git history, real `.env`, SDK authentication/signing, Telegram, accounts/orders/positions/balances/receipts/recovery stores, raw third-party archives, logs, screenshots, backups, compressed files, virtual environments and local service configuration.

Validation uses a fresh Python virtual environment without pip or third-party site packages. The supported demo and 18 offline tests cover four replay engines, cash continuity, input hashes, import-without-write behavior, forbidden network/credential/database access, H2's actual time branch, S2 distinct timestamps/quality reset, A1's wider filter, realized-versus-reserved quantity selection, and Minimax's tie/unknown-data/residual/scenario limits. The private source differential check compares original fresh initialization against the release with exact full synthetic-ledger equality for all four strategies. AST identities and source/export hashes are recorded in [source_manifest.json](../provenance/source_manifest.json).

Before push, inspection covers every allowlisted working file, exact staged blob, proposed commit's entire reachable history, commit metadata/messages and actual tracked-file names. Pattern classes include key/signature/credential markers, provider token shapes, wallet addresses, high-entropy strings, email/IP/path indicators and excluded file types. Matches are reviewed without printing candidate values. A 64-character hash in a provenance field is treated differently from an unlabelled secret. The repository's requested public owner/name is the only intentional personal identifier. The scanner's coverage and reviewed findings are summarized in [verification.json](../provenance/verification.json).

**Within the checked scope, no unapproved sensitive information was found.** This is a bounded inspection, not an absolute safety guarantee. It does not scan or certify excluded private files, determine every possible secret format, establish legal title independently, verify old winner labels, reproduce historical returns or prove profitability. The offline guard is a process-wide research guardrail, not an adversarial Python sandbox. Uploaded GitHub files and the local candidate tree are compared before changing visibility.

检查结论仅限所检查范围；不承诺绝对安全，不把隔离测试当作真实成交、历史收益复现或持续盈利证明。
